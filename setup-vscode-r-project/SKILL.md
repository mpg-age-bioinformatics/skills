# Set up an R project in VS Code

Work from the current repository root. This is a one-time project bootstrap for an interactive R development workflow. Perform the initial setup idempotently and preserve existing files, but do not rerun the skill after ordinary source-code, analysis, or dependency changes. After setup, the user and agent develop scripts incrementally inside the configured Dev Container.

1. Obtain the R version from the caller. Accept `major.minor` or `major.minor.patch`, such as `4.4` or `4.4.2`. Resolve either form to its `major.minor` Rocker image tag, so `4.4.2` selects `ghcr.io/rocker-org/devcontainer/r-ver:4.4` and therefore the latest published patch release in the R 4.4 series. If the caller did not provide a version, ask for it before changing the repository; do not silently choose the newest R series.
2. Run `scripts/setup-project.sh` with the absolute repository root as the first argument and the requested R version as the second. Do not recreate its copying, substitution, or Git operations manually.
3. The script clones `https://github.com/mpg-age-bioinformatics/skills.git` into `skills/` at the project root when that path is absent. It ignores `skills/` in the project repository so the nested clone is not accidentally committed. On later runs it preserves an existing clone only when its `origin` is the requested repository; it does not pull, reset, overwrite, or replace it, and stops if `skills/` has another origin or is not a Git clone. The Dev Container mounts the clone read-only at `/home/rstudio/.codex/skills` and `/home/rstudio/.claude/skills`, making the same collection discoverable by Codex and Claude.
4. The script creates `code/`, `data/`, `.devcontainer/`, and `.vscode/` when needed. It preserves existing files and creates ignored, owner-only `.codex-home/` and `.claude-home/` directories. The Dev Container runs as Rocker's `rstudio` user and mounts them at `/home/rstudio/.codex` and `/home/rstudio/.claude` so project-specific Codex and Claude state survives rebuilds. It also creates an ignored `.r-library/` directory, mounts it at `/home/rstudio/R/library`, and sets `R_LIBS_USER` to that path so user-installed R packages survive container rebuilds without entering Git.
5. The generated container uses `ghcr.io/rocker-org/devcontainer/r-ver:<major.minor>`, never a patch-level image tag. Its R tooling includes VS Code R support, `languageserver`, `httpgd`, `renv`, and R Markdown support. During subsequent interactive development, the agent adds or updates dependency installation code and `renv.lock` as packages become necessary; package changes do not trigger another setup-skill run. The generated agent guidance requires every package installation instruction to be recorded in tracked code or a tracked dependency manifest, pins every package to an exact version, and requires installation code and `renv.lock` to be updated together. When adding a dependency, the agent must also adapt each affected script to activate the same `renv` or project library before loading packages, then verify in a fresh R process that the package resolves from the intended location. The guidance defines analysis scripts as incremental, sectioned R/RStudio workflows with a top-level configuration section, inspectable intermediate objects, validation after data loading, outputs under `data/`, no prompt-driven interface unless requested, and reproducibility when run top to bottom from the project root. VS Code is configured with the primary sidebar on the left so Explorer stays on the left and the secondary Agents view stays on the right, the script editor in the main area, the integrated R terminal in the bottom panel, plots through the HTTP graphics device, tables through the R data viewer, and Codex and Claude in the activity bar. Explain that VS Code owns final per-view placement and may require the user to drag views once; extensions cannot reliably force a permanent four-pane layout.
6. If a commit fails because Git author identity is missing, do not configure or invent an identity. Leave the files staged and tell the user to configure `user.name` and `user.email`, then rerun the skill.
7. Reopen the folder using `Dev Containers: Reopen in Container` when a supported VS Code command interface is available. Otherwise, say `The VS Code CLI isn't available here. In VS Code's Command Palette, run:` and then put the exact literal line `>Dev Containers: Reopen in Container` in a fenced code block. Never claim the folder was reopened unless it actually was.
8. After the container starts, verify `R --version` reports a version in the requested `major.minor` series, `Sys.getenv("R_LIBS_USER")` reports `/home/rstudio/R/library`, and the cloned skills are visible at both agent discovery paths. Tell the user how to open the working views: open an `.R` file, run `R: Create R terminal`, use `httpgd::hgd()` for the plot viewer when it is not started automatically, and use `View(object)` for a table. Mention that the Codex and Claude extensions are available from the activity bar.
9. Warn that `.codex-home/` and `.claude-home/` contain sensitive plaintext state and credentials and must remain uncommitted and private.

Do not overwrite an existing Dev Container or VS Code configuration. If either prevents the requested setup, report the conflicting path and stop. Do not add unrelated runtimes, host credential mounts, or host filesystem mounts.
