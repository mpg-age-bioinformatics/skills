# Set up an R Docker Sandbox

Work from the current repository root. This is a one-time bootstrap. Perform setup idempotently, preserve existing files, and do not rerun it after ordinary code, analysis, or package changes.

1. The caller must supply both the R version and agent (`codex` or `claude`). Accept `major.minor` or `major.minor.patch` and normalize either to `major.minor`, selecting the latest Rocker patch published for that series. If either input is absent, make one direct question for the missing value or values as the first response, before checks, setup, explanation, or other action.
2. Run `scripts/setup-project.sh` with the absolute repository root, requested R version, and agent. Do not recreate its generation, cloning, or Git operations manually.
3. The script creates `code/`, `data/`, `.r-library/`, and `.vscode/`; clones `https://github.com/mpg-age-bioinformatics/skills.git` into ignored `skills/`; and installs `code/Dockerfile`, `code/run-r-sandbox.sh`, the agent-specific `code/Run R Sandbox.exe`, project guidance, VS Code configuration, and LF-only Git attributes for shell launchers. It preserves existing files and stops on conflicts. When `R_SANDBOX_SKILLS_REF` is set, the project-local skills clone uses that exact revision.
4. `code/Dockerfile` is a tracked recipe for rebuilding the sandbox template. All arguments used by `FROM` are declared before the first `FROM`. It sources R from `ghcr.io/rocker-org/devcontainer/r-ver:<major.minor>`, installs `BiocManager` before the pinned editor-tooling package `languageserver` 0.3.18, copies the R runtime, site library, and required shared libraries into the selected Codex or Claude sandbox template, and installs the standard C, C++, and Fortran build toolchain plus common development headers used by CRAN and Bioconductor packages. It verifies `R`, `Rscript`, compiler configuration, `BiocManager`, and the exact `languageserver` version during the build. Docker requires the final image to extend the matching agent template, so the Rocker image cannot itself be the final sandbox image.
5. Generated guidance preserves the interactive, sectioned R/RStudio workflow from `setup-vscode-r-project`. Project dependencies use exact versions with `renv`; installation code and `renv.lock` change together; scripts activate the same project library before loading packages; and outputs go under `data/`. Scientific work must use appropriate CRAN or Bioconductor libraries rather than dependency-avoidance fallbacks. In particular, CSV-backed heatmaps use `readr::read_csv()`, `circlize::colorRamp2()`, and a direct `ComplexHeatmap::Heatmap(...)` call by default, then save the rendered result with `ComplexHeatmap::draw()`; base `image()` or manually constructed heatmaps are prohibited unless the user explicitly requests them.
6. If setup commit fails because Git author identity is missing, do not invent one. Leave files staged and tell the user to configure `user.name` and `user.email`, then rerun the skill.
7. Verify `sbx` 0.39.0 or newer. On macOS, check the daemon and run `sbx daemon start --detach` when it is not already reachable, waiting up to 15 seconds for readiness before diagnostics. If `sbx` is absent or older, stop after repository setup and direct the user to Docker's installation documentation. Do not install host software or start authentication without authorization.
8. Invocation authorizes the normal template build, sandbox launch, SSH setup, VS Code User configuration, extension installation, and Remote-SSH connection. Treat configuration as enabled by default and skip only when the caller explicitly opts out.
9. Merge `.vscode/settings.json`'s `remote.SSH.defaultExtensions` IDs into the local VS Code **User** setting, preserving existing entries. The launcher also installs and verifies extensions directly in the remote. Generated workspace settings set `extensions.ignoreRecommendations` to `true` only because every repository recommendation is a required extension handled before the workspace opens; this suppresses the redundant “install recommended extensions” prompt without replacing installation.
10. Run `code/run-r-sandbox.sh codex`, `code/run-r-sandbox.sh claude`, or double-click the generated `code/Run R Sandbox.exe` on Windows. It verifies `sbx` and a Linux-container Docker daemon, builds and imports the agent-matched template, creates or reconnects in detached mode to a path-derived sandbox, sets `R_LIBS_USER` to the mounted project `.r-library/`, verifies the requested R series and `languageserver` 0.3.18, and only then opens VS Code. On Windows, only local-drive workspaces are supported, and native host paths remain separate from the `/c/...` paths used inside the sandbox and by VS Code Remote-SSH. The language server is image tooling, not a project dependency, so it is installed before repository `renv` work and must never trigger an interactive VS Code installation prompt.
11. The launcher runs `sbx setup ssh`, force-installs Remote-SSH locally, then force-installs R, R Debugger, Quarto, Codex, and Claude into the SSH remote before opening the repository. It must list the extensions from that remote authority and verify every required ID; if R Debugger, Quarto, or another required extension is absent, stop with the installation error instead of opening VS Code. Together with `extensions.ignoreRecommendations`, this guarantees the repository never opens in a state that asks whether to install R Debugger or Quarto. If `code` is absent from `PATH`, discover the bundled macOS CLI, enable `/usr/local/bin/code` when writable, or invoke the bundled CLI directly. Do not finish with manual connection instructions unless automatic opening fails.
12. Verify `R --version` and `R.version` are in the requested series, `.libPaths()` includes the project `.r-library/`, and skills are visible to both agents. Explain that VS Code may require one-time manual view placement; use `R: Create R terminal`, `httpgd::hgd()` for plots when needed, and `View(object)` for tables.

Do not create `.devcontainer/`, mount `/var/run/docker.sock`, persist plaintext agent homes in the repository, add host credential mounts, or remove a sandbox. Credential setup and sandbox removal require separate authorization.

## Standalone shell entrypoint

`assets/r-sandox.sh` accepts `<R-version> <codex|claude> [project-directory]`, prompts for missing required values before doing work, runs deterministic host-side scaffolding, and starts the selected agent only inside Docker Sandbox. It uses the same launcher, so all required remote extensions are force-installed and verified before the connected VS Code workspace opens.
