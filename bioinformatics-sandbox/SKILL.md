# Set up a bioinformatics Docker Sandbox

Work from the current repository root. This skill configures the repository; Docker Sandbox creation remains an explicit user-selected launch because each sandbox runs one chosen agent.

1. Run `scripts/setup-project.sh` with the absolute repository root. Do not recreate its copying, cloning, or Git operations manually.
2. The script creates `code/`, `data/`, and `.vscode/`, clones `https://github.com/mpg-age-bioinformatics/skills.git` into ignored `skills/`, installs the launcher at `code/run-bioinformatics-sandbox.sh`, and adds root `AGENTS.md`, `.instructions.md`, extension recommendations, and workspace settings. It preserves existing files and stops on conflicts.
3. The generated policy keeps scientific code, Dockerfiles, and dependency manifests under `code/`, data and outputs under `data/`, and requires appropriate scientific libraries. It explicitly requires CSV-backed heatmaps to use Pandas with Seaborn/Matplotlib and a direct `sns.heatmap(...)` call by default; missing packages must be added as pinned dependencies rather than replaced with manual CSV parsing, SVG/XML construction, color interpolation, or custom heatmap rendering. Workload containers are built and run only when dependencies or isolation require them. They run on the Docker daemon private to the Docker Sandbox, never through a host Docker socket or a VS Code Dev Container.
4. If the setup commit fails because Git author identity is missing, do not invent or configure one. Leave files staged and ask the user to configure `user.name` and `user.email`, then rerun the skill.
5. Verify the host has `sbx` 0.37.0 or newer with `sbx version`; VS Code Remote-SSH integration requires that version. If it is absent or older, stop after repository setup and direct the user to Docker's installation documentation. Do not install host software or start authentication flows without explicit permission.
6. Ask which agent to launch only if the caller has not selected one. Run `code/run-bioinformatics-sandbox.sh codex` or `code/run-bioinformatics-sandbox.sh claude` from the repository root. The launcher uses a stable repository-derived sandbox name and the current workspace as a direct read-write mount. Explain that direct mode exposes the repository but not the rest of the host; offer Docker Sandbox clone mode separately when the user wants the host working tree isolated.
7. Before the first VS Code connection, ensure the local VS Code client has `ms-vscode-remote.remote-ssh` installed. Merge the IDs from `.vscode/settings.json` under `remote.SSH.defaultExtensions` into the local VS Code **User** setting of the same name, preserving any existing entries. This local setting is what makes VS Code install workspace extensions into a new SSH Remote Extension Host during connection; `.vscode/extensions.json` recommendations alone are insufficient. Changing local User settings is outside the repository, so do it only with user authorization. If no supported settings interface is available, show the exact JSON property for the user to add manually.
8. Run `sbx setup ssh` when authorized, ensure the sandbox is running, connect with Remote-SSH to the hostname printed by the launcher (`<sandbox-name>.sbx`), and open the same absolute project path. Confirm the Python, Pylance, Jupyter, R, Codex, and Claude extensions appear under `SSH: <sandbox-name>.sbx - Installed`, not only under `Local - Installed`. If an extension cannot install, report the Marketplace or network error rather than claiming setup is complete. Never claim VS Code connected or extensions are enabled unless verified.
9. Explain that Docker Sandboxes use a microVM boundary with a private filesystem, network, and Docker daemon. The built-in `-docker` agent templates may run workload containers with privilege inside that microVM, but they do not expose the host Docker daemon. Sandbox-installed packages, images, containers, and remotely installed VS Code extensions persist across sandbox stops and are discarded when the sandbox is removed.

Do not create `.devcontainer/`, mount `/var/run/docker.sock`, persist plaintext agent homes in the repository, add host credential mounts, or remove a sandbox. Credential setup and sandbox removal require explicit user authorization.
